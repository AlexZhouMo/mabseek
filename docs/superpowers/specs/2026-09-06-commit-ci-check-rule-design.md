# 提交前检查「一键部署脚本可持续集成」规则 — 设计

**日期：** 2026-09-06
**状态：** 已确认，待实施
**类型：** 项目规则 + 文档（无代码逻辑改动）

## 背景

MabSeek 生产环境部署在阿里云，通过 `deploy/deploy-mabseek.sh` 一键部署/更新，支持在线（GitHub git 拉取）与离线（`pack-mac.sh` 打的 tar 包）两种模式。两种模式都**保留生产数据库 `data/` 与上传目录**，且 `data/*.sqlite` 被 `.gitignore` 排除、不随代码同步。

近期两次改动（全站图片转 WebP、联系邮箱订正）都暴露了同一个坑：**改动涉及数据库内容时，仅改代码或 seed 不够** —— 因为 `data/` 不进 git、`seed.php` 是「有数据即跳过」，生产库里的历史记录不会被更新，导致线上出现死链或旧值。两次都通过「改 seed 种子 + 写幂等迁移脚本 + 接入部署脚本」解决。

本设计把这套已被验证的实践**固化为项目级强制规则**，防止未来提交遗漏部署链路。

## 目标

- 新建项目根 `CLAUDE.md`，写入一条强制规则：提交到 GitHub 前必须确认一键部署脚本能让本次改动在阿里云生产环境正常持续集成。
- README「部署」节同步一段人类可读摘要，指向 CLAUDE.md 作为权威来源。

## 非目标（YAGNI）

- **不**添加 Git pre-commit / pre-push 钩子（用户选择纯 CLAUDE.md 落地）。
- **不**修改现有部署脚本逻辑（`deploy-mabseek.sh` / `pack-mac.sh` 已在前两次改动中验证可用）。
- **不**改动 `docs/` 下的历史设计/计划归档。

## 规则内容（写入 `CLAUDE.md`）

核心是一个**提交前检查清单**：

> **【强制】提交到 GitHub 前，必须确认「一键部署脚本」能让本次改动在阿里云生产环境正常持续集成。**
>
> **触发条件：** 改动涉及代码、静态资源、数据库内容、部署脚本、seed 或迁移脚本时执行本检查。**纯文档 / 纯注释、不影响部署链路的改动可跳过**（在提交信息里注明「无部署影响」）。
>
> **逐项核对：**
>
> 1. **数据库变动同步** — 若改动涉及数据库里的内容（`snippets` 文案、各表记录等）：因 `data/*.sqlite` 不进 git、`bin/seed.php` 有数据即整表跳过，**必须同时**做到：
>    - 更新 `bin/seed.php` 里的种子默认值（保证全新部署正确）；
>    - 编写幂等迁移脚本 `bin/migrate-*.php`（就地订正历史库存量记录）；
>    - 在 `deploy/deploy-mabseek.sh` 的 seed 步骤之后接入该迁移脚本调用。
> 2. **静态资源完整** — 若新增 / 改名图片、CSS、JS：确认文件已 `git add`、代码引用路径已更新、且未被 `.gitignore` 排除。
> 3. **迁移幂等安全** — 新迁移脚本必须幂等（可反复运行，无旧值时 0 改动），且不误伤用户数据（`public/assets/images/uploads/` 上传图、管理员在后台改过的文案）。
> 4. **双部署模式覆盖** — 确认在线（git 拉取）与离线（`pack-mac.sh` 打包的 tar）两种模式都能拿到本次变动，尤其 `pack-mac.sh` 的打包范围覆盖新增文件。
>
> **验证方式（实测）：** 涉及数据库 / 迁移脚本的改动，须用临时库模拟生产「旧状态」实测：跑迁移脚本、验证幂等（二次运行 0 改动）、验证页面渲染正确；并对改动的 PHP / bash 文件跑 `php -l` / `bash -n` 语法检查。仅纯文档 / 纯注释改动可省略实测。

## README 更新（`README.md`「部署」节末尾新增）

> **提交前检查（持续集成保障）**
>
> 提交到 GitHub 前，须确认一键部署脚本能让本次改动在生产环境正常集成。重点：数据库内容改动（`data/` 不进 git、seed 有数据即跳过）必须配套 `seed.php` 种子更新 + 幂等迁移脚本（`bin/migrate-*.php`）+ 接入 `deploy-mabseek.sh`；静态资源须确认已入库且引用已更新；迁移脚本须幂等且不误伤用户数据；在线 / 离线两种部署模式都要覆盖。完整规则见 [CLAUDE.md](CLAUDE.md)。
